# arpwatch — ARP spoofing monitor

Detects Layer-2 ARP anomalies (IP→MAC binding changes, gratuitous ARP,
flip-flopping, duplicate addresses) on the LAN via the switch mirror port.
Runs as a rootful Podman container managed by a systemd quadlet.

## What it does

- Watches ARP traffic on the mirrored interface and learns IP→MAC bindings
- Reports `new station`, `changed ethernet address`, `flip flop`, and
  `reused old ethernet address` events — the signatures of ARP spoofing /
  man-in-the-middle attempts
- Detection only: it logs alerts, it does not block anything

## Watched interface

`enp0s20f0u10` — USB NIC cabled to the TL-SG105E mirror destination port.
Receives copies of all LAN ARP broadcasts.

## Image

`localhost/arpwatch:latest` — built from `Dockerfile` in this directory
(`jasonish/suricata` base + `arpwatch` package, entrypoint `/usr/sbin/arpwatch`).

## Logging

Reports go to the host journal via the container's stdout and `/dev/log`:

```bash
journalctl -t arpwatch -f          # live ARP reports
journalctl -u arpwatch.service     # unit logs
```

## State

Learned IP→MAC database persists at `/var/lib/arpwatch-data/arp.dat`
(mounted to `/var/lib/arpwatch` in the container) so bindings survive
restarts and `new station` reports aren't repeated.

## Unit / files

- Quadlet: `/etc/containers/systemd/arpwatch.container`
- Unit name: `arpwatch.service` (generated by quadlet generator)

## Rebuild / rerun

```bash
# rebuild image after Dockerfile changes
podman build -t localhost/arpwatch:latest \
  /var/home/kim/workspace/suricata-containerized-rootful/arpwatch/

# restart the service
systemctl restart arpwatch.service
systemctl status arpwatch.service
podman logs -f arpwatch
```

Manual one-off run (debug, foreground):

```bash
podman run --rm --network host \
  --cap-add NET_RAW --cap-add NET_ADMIN \
  -v /dev/log:/dev/log \
  localhost/arpwatch:latest arpwatch -d -i enp0s20f0u10
```
