Detection pipeline

  • Rules: Emerging Threats Open via suricata-update — 69,570 fetched, ~53,590 enabled. Daily timer suricata-update-rules.timer (03:30) regenerates rules, config-tests, then restarts both engines.
  • FP tuning: /var/lib/suricata-ids/config/disable.conf disables noisy rules (ethertype-unknown mirror noise, ICMP ping spam, TP-Link admin UI false hits). drop.conf converts trojan-activity / command-and-control classtypes to drop actions (~19k rules).
  • Shared config: both containers mount /var/lib/suricata-ids/{config,rules} read-only and use the same suricata.yaml (HOME_NET = 192.168.1.0/24).
  • Local rules: local.rules adds host-specific alerts (ICMP, SSH, Telnet, RDP, SMB, DNS).

CF  suricata-cf-block

  • Rootless podman container managed by podman compose — manifest: /var/home/workspace/suricata-containerized-rootful/compose.yaml (also mirrored in this repo as suricata-cf-compose.yaml).
  • Script: /usr/local/sbin/suricata-cf-block.py — tails both eve.json files.
  • Flags: IPS alerts with action:"blocked"; IDS alerts in high-confidence categories (trojan-activity, command-and-control, domain-c2).
  • Public IPs only (RFC1918/CGNAT/loopback skipped), deduped, batched to a Cloudflare account List suricata-blocked via API.
  • Status: awaiting CF_API_TOKEN in /var/lib/suricata-cf-block/cf.env. List alone doesn't enforce — needs a Gateway/WAF policy referencing it.

Operational notes

  • Mirror ≠ IPS: the AF_PACKET instance can never drop traffic — prevention for the whole LAN requires an inline bridge or on-path device.
  • NFQUEUE = this host only: other LAN hosts' traffic isn't inspected by the IPS.
  • Both engines run with fail-open behavior — Suricata outages don't take the network down.
  • Realtek USB NIC emits loopback-test frames that appear on the mirror — disabled rule 2200121 filters the resulting noise.
  • Rule reload requires container restart (no suricatasc command socket); daily timer handles this automatically.
